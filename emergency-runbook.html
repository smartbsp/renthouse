想拔電也來不及,LED 還沒滅完它又啟動 ### 根本原因 QTS 的「**電源回復**」設定預設 = **`POWER_ON`(總是開機)**。 - SSH `/sbin/poweroff` 直接觸發 BIOS 級 ATX 斷電 - BIOS 把這個看成「**意外斷電**」,不是使用者主動關 - → 觸發 Power Recovery = POWER_ON → 自動再開機 ### 正確關機方式(3 選 1) **方式 A:用 QTS Web UI 關機(最簡單,推薦)** 1. 瀏覽器進 `http://192.168.0.100:8080` 2. 右上角頭像 → **「關機」** → 確認 3. Web UI 關機走「軟關機」flag,BIOS 知道是使用者主動關,不會觸發 Power Recovery 4. 等 LED 全滅 → 拔電 → 想搞多久搞多久,不會自己再開 **方式 B:先改 Power Recovery 設定,再 SSH 關** 1. QTS 控制台 → **系統** → **電源** → **配置** 2. 「**系統當機 / 斷電 → 系統啟動**」設定改成 **「保持上次的狀態」(LAST_STATE)** 或 **「關閉」(POWER_OFF)** 3. 套用後再 SSH `poweroff` 就會真的關 4. ⚠️ 之後插電進來,LAST_STATE = 看你關時是 ON 還 OFF / POWER_OFF = 一定要手動按電源鍵才開 **方式 C:長按電源鍵 + 立刻拔電(粗暴但確定)** 1. 長按 NAS 前面板電源鍵 **5–10 秒** → BIOS 級強制斷電 2. LED 一滅 **立刻拔背面電源線**(秒級) 3. 因為線拔了,Power Recovery 沒得觸發,NAS 留在斷電狀態 4. ⚠️ 「立刻」是真的「立刻」 — Power Recovery 觸發 boot 只需要 1–2 秒 ### 為什麼 2026-06-09 這場踩雷 - 我(Claude)第一次提的指令是 `ssh nas "sudo poweroff"` — 在 QNAP 上 `sudo` 不存在,silent fail 第一次沒關到 - 第二次用 `/sbin/poweroff` 真的關了,但 Power Recovery = POWER_ON 把它叫醒了 - 教訓:**QNAP 上關機優先用 Web UI**,SSH `poweroff` 是 BIOS 級操作,要配合 Power Recovery 設定 ### 一勞永逸建議 升硬體前,先把 Power Recovery 改成 **`POWER_OFF`** 或 **`LAST_STATE`** → 之後 SSH `poweroff` 也能放心關 → 升完硬體再改回 POWER_ON(或就維持 LAST_STATE,通常是最聰明的)。 --- ##
